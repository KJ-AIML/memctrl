Your user config holds the settings only you should make: how strict the write guard is, which repositories you trust, and whether memctrl may send text to an embedding model. A repository's [`.memoryrc`](/memctrl/reference/memoryrc/) arrives with every clone, so it can make these settings stricter but never looser than this file allows.

## Where it lives

| Platform | Path |
| --- | --- |
| macOS, Linux | `$XDG_CONFIG_HOME/memctrl/config.toml` when `XDG_CONFIG_HOME` is set and not empty, else `~/.config/memctrl/config.toml` |
| Windows | `%APPDATA%\memctrl\config.toml` |

memctrl reads the file on every command, and the MCP server reads it again for every tool call. A missing file means the defaults. A file that isn't valid TOML, or holds an invalid value under `[guard]` or `[trust]`, makes every command fail with the reason on stderr, so a typo can't quietly weaken a setting. A mistake under `[semantic]` only turns search by meaning off, with a warning on stderr, so commands and hooks keep working without it (2.6.2 and earlier failed every command). `memctrl semantic status` prints the path it uses under `config`.

The file has three sections. Other sections and keys are ignored, except in `[semantic]`, where an unknown key turns search by meaning off with a warning.

## [guard]

| Key | Type | Default | What it does |
| --- | --- | --- | --- |
| `mode` | `"off"`, `"flag"` or `"strict"` | `"flag"` | `flag` holds new memories with hidden Unicode or instruction-like text as candidates for your review. `strict` also holds every write from a source not in `trusted_sources`. `off` inspects nothing. This is the least protective mode a repository can use. |
| `trusted_sources` | array of strings | `["manual", "user", "cli"]` | The sources `strict` mode doesn't hold, and whose `user`-layer facts and observations the brief shows under "From the user" (and recall labels `[from the user]`). A repository can only narrow this list. |

A memory's source is a label on the write, not proof of who made it:

| Source | Where it comes from |
| --- | --- |
| `manual` | `memctrl add` without `--source`, whoever runs it, you or an agent in its shell. |
| `mcp` | `memctrl_add` over MCP without a `source` argument. |
| `import` | Hand-written bullets imported from `memory.md`. |
| `trigger` | Candidates proposed by a `summarize` trigger. |
| `heuristic_extract` | Memories saved by an `extract` trigger. |
| `user`, `cli` or any other name | Only writes that name it: `memctrl add --source user`, or `source` on `memctrl_add`. |

memctrl doesn't record who typed a memory, so an agent's `memctrl add --layer user` counts as `manual`, like yours. To keep an agent's ordinary writes out of "From the user", trust `user` alone and save your preferences with `--source user`. That isn't proof of who wrote a memory: an agent can pass `--source user` too.

```toml title="~/.config/memctrl/config.toml"
[guard]
trusted_sources = ["user"]
```

```bash
memctrl add "Prefers small pull requests with one change each" --layer user --source user
```

See [Guard and trust](/memctrl/concepts/guard-and-trust/) for what the guard looks for and how held memories are released.

## How your settings combine with .memoryrc

In a repository you haven't trusted, memctrl starts from your user config and applies the repository's `.memoryrc` on top, keeping only what tightens:

| Setting | Result |
| --- | --- |
| `[guard] mode` | The stricter of yours and the repository's. A `.memoryrc` with the built-in value, which `memctrl init` writes, yields to yours. |
| `[guard] trusted_sources` | If the `.memoryrc` lists sources, those that are also in yours. Otherwise, or when it lists exactly the built-in sources, yours. |
| `[forget] never` | The built-in words plus any the repository adds. |
| `[semantic]` | Yours only. |

`memctrl init` writes `mode = "flag"` and `trusted_sources = ["manual", "user", "cli"]` into every `.memoryrc`. Those are the built-in values, not a choice the repository made, so where your config sets `mode` or `trusted_sources`, yours applies over them, looser or stricter, without a warning. With `mode = "off"` in your config, a repository whose `.memoryrc` still has the template lines runs with the guard off; with `trusted_sources = ["user"]`, it trusts only `user`. A repository that sets any other value keeps the usual rule: the stricter one wins. A repository you [trust](#trust) applies its file in full, template lines included.

<Aside type="caution" title="2.6.2 and earlier">
Before 2.6.3, the template's lines held a repository at the built-in values when your config was looser. To use `mode = "off"` or an extra trusted source there, delete those lines from its `.memoryrc`, or trust the repository.
</Aside>

The full list of what a repository can't loosen is in [`.memoryrc`](/memctrl/reference/memoryrc/#settings-a-repository-can-only-tighten).

## [trust]

| Key | Type | Default | What it does |
| --- | --- | --- | --- |
| `repos` | array of strings (paths) | `[]` | Repositories whose `.memoryrc` applies in full, loosening included, and whose committed database memctrl loads. |

Each entry is an absolute path, or starts with `~/`, which expands to `HOME` (or `USERPROFILE` when `HOME` isn't set). A relative path is an error. memctrl compares an entry with the repository that holds the `.memoryrc`: the nearest folder at or above it that contains `.git`.

```toml title="~/.config/memctrl/config.toml"
[trust]
repos = ["~/code/our-team-repo", "/srv/checkouts/platform"]
```

Trust a repository only if you trust everyone who can push to it. Even then, a `[semantic]` section in its `.memoryrc` is ignored.

## [semantic]

[Search by meaning](/memctrl/concepts/search-by-meaning/) is off until this section exists. With it, `query`, the MCP server and the prompt hook also match memories by meaning, using an embedding model you run. [Set up search by meaning](/memctrl/guides/set-up-search-by-meaning/) walks through it.

| Key | Type | Default | What it does |
| --- | --- | --- | --- |
| `model` | string | required | The name your server knows the model by. memctrl also uses it to pick the model's prefixes and measured thresholds. |
| `base_url` | string (URL) | `"http://localhost:11434/v1"` | Any OpenAI-compatible server; memctrl posts to `<base_url>/embeddings`. Must be `http` or `https`, with no user name, password, query or fragment. |
| `enabled` | boolean | `true` | `false` keeps the section but turns search by meaning off. |
| `threshold` | number from -1 to 1 | measured value for the model | The similarity a memory found by meaning alone needs to be returned by `query`. |
| `recall_threshold` | number from -1 to 1 | measured value for the model, else `threshold` | The same for the prompt hook, which nobody asked. It's never lower than `threshold`. |
| `query_prefix` | string | set from the model name | Text put before a query or prompt when it's embedded. |
| `document_prefix` | string | set from the model name | Text put before a memory when it's embedded. |
| `dimensions` | positive integer | all | Keep only the first this many dimensions (Matryoshka models such as EmbeddingGemma). |
| `timeout_ms` | positive integer | `3000` | How long a search waits for the server. `semantic index` waits up to 120 seconds per batch. |
| `api_key_env` | string | none | The name of the environment variable that holds a key, sent as a bearer token. If the variable isn't set, search by meaning is off with a warning. |
| `allow_remote` | boolean | `false` | Must be `true` for a server that isn't on this machine (anything but `localhost` or a loopback address), which must also use `https`. |

memctrl knows these models by a lowercase substring of `model`, most specific first:

| Model name contains | `query_prefix` | `document_prefix` | `threshold` | `recall_threshold` |
| --- | --- | --- | ---: | ---: |
| `embeddinggemma` or `embedding-gemma` | `task: search result \| query: ` | `title: none \| text: ` | 0.455 | 0.56 |
| `multilingual-e5-small` | `query: ` | `passage: ` | 0.849 | 0.85 |
| `e5-` | `query: ` | `passage: ` | none | none |
| `nomic-embed-text` | `search_query: ` | `search_document: ` | none | none |
| `mxbai-embed` | `Represent this sentence for searching relevant passages: ` | none | none | none |
| `qwen3-embedding` | `Instruct: Given a web search query, retrieve relevant passages that answer the query` and a new line, then `Query:` | none | none | none |

Without a measured or configured `threshold`, search by meaning stays off with a warning (`memctrl semantic status` shows the reason) until you add the values [`memctrl semantic tune`](/memctrl/reference/cli/semantic/) prints. Without a threshold every question would return something.

Changing `model`, `document_prefix` or `dimensions` starts a new set of stored vectors; vectors made with other settings are never mixed in. To turn search by meaning off for one command, set `MEMCTRL_SEMANTIC=off`.

## Examples

### Keep agents' ordinary writes out of "From the user"

```toml title="~/.config/memctrl/config.toml"
[guard]
trusted_sources = ["user"]
```

### Hold everything agents write over MCP

```toml title="~/.config/memctrl/config.toml"
[guard]
mode = "strict"
trusted_sources = ["manual", "user", "cli"]
```

Every `memctrl_add` (source `mcp`) then arrives as a candidate tagged `guard:untrusted_source`. So does every entry `memctrl import` and `memctrl sync` bring in from `memory.md`, even with `--accept`, because imports are checked as source `import`.

### Everything together

```toml title="~/.config/memctrl/config.toml"
[guard]
mode = "flag"
trusted_sources = ["user"]

[trust]
repos = ["~/code/our-team-repo"]

[semantic]
model = "embeddinggemma"
base_url = "http://localhost:11434/v1"
```
