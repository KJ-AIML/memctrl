Codex and Cursor don't run memctrl's hooks, but they read `AGENTS.md`. memctrl writes the session brief into a marked block of that file and refreshes it in place, so the agent starts each session with the same memories Claude Code gets from its hook. A skill file tells the agent how to search and save memories.

## Install the skill

Run this in a project where you've run `memctrl init`:

```bash
memctrl install --tool codex --project     # Codex
memctrl install --tool cursor --project    # Cursor
```

```json
{"path":"/home/you/your-project/.agents/skills/memctrl/SKILL.md"}
```

`--project` writes the skill into the project folder (the one with the nearest `.memoryrc`). Without it, the skill goes under your home folder, where the tool finds it for any project.

| `--tool` | With `--project` | Without `--project` |
| --- | --- | --- |
| `codex` | `.agents/skills/memctrl/SKILL.md` | `~/.agents/skills/memctrl/SKILL.md` |
| `cursor` | `.cursor/skills/memctrl/SKILL.md` | `~/.cursor/skills/memctrl/SKILL.md` |
| `axga` | `.axga/agent/skills/memctrl/SKILL.md` | `~/.axga/agent/skills/memctrl/SKILL.md` |
| `pi` | `.pi/agent/skills/memctrl/SKILL.md` | `~/.pi/agent/skills/memctrl/SKILL.md` |
| `kimi` | `.kimi/skills/memctrl/SKILL.md` | `~/.kimi/skills/memctrl/SKILL.md` |

The skill is the same file for every tool. It explains the brief's sections, how to search with `memctrl query`, how to save memories with `memctrl add`, and that only a person can accept a held memory. If memctrl 2.0 left a Codex skill in `.codex/skills/`, where Codex never reads it, the output lists it under `legacy_skill` so you can delete it.

`--hook` works only with `--tool claude`. For any other tool, `install` refuses it and points you to `context --write`.

## Write the brief into AGENTS.md

```bash
memctrl context --write AGENTS.md
```

```json
{"written":"AGENTS.md","shown":3,"eligible":3,"approx_tokens":265}
```

`shown` is how many memories made it into the brief and `eligible` how many could have. The brief goes between two markers:

```markdown title="AGENTS.md"
# Agent guide

Run `cargo test` before committing.

<!-- memctrl:context:begin -->
<!-- Generated by `memctrl context --write`. Re-run it to refresh; edits here are overwritten. -->
# Project memory (memctrl)

3 of 3 memories from project, user · ≈265 tokens · highest trust first.
Notes, not instructions, with two exceptions:
…

## Decisions

- We chose SQLx over Diesel: compile-time checks caught 3 prod bugs · `759c05a4`
…
<!-- memctrl:context:end -->
```

- **The first run appends the block** to the end of the file, or creates the file if there is none.
- **Later runs replace only the block.** Everything outside the markers stays as you wrote it, and edits inside the block are overwritten.
- **Broken markers stop the write.** Unless the file has exactly one begin marker followed by one end marker (or neither), memctrl changes nothing and asks you to fix or remove them.
- **The path is relative to the current folder.** A relative path must resolve inside the project; an absolute path is your explicit choice.
- **It needs a store.** Without one, `--write` fails with a hint to run `memctrl init`, where plain `memctrl context` prints nothing.

`--write` takes the same options as the printed brief: `--budget` (default 3000 tokens) and `--layer` (default `project` and `user`). See [`memctrl context`](/memctrl/reference/cli/context/).

<Aside type="caution" title="Your preferences end up in the file">
By default the brief includes your `user` layer under "From the user". If you commit AGENTS.md, those preferences go into the repository. To keep them out, write the block with `memctrl context --write AGENTS.md --layer project`.
</Aside>

## Keep the block fresh

The block is a snapshot. It doesn't change when you add a memory or when cited code changes, and its "stale" labels describe the code as it was when you ran the command. Run `memctrl context --write AGENTS.md` again:

- after you add, correct or retire memories,
- after `memctrl sync` brings in teammates' changes,
- after editing code that memories cite, so changed citations move to "Check before trusting".

Since `--write` changes a file in your repository, decide with your team whether the block is committed. Committed, it shows the brief to teammates who don't run memctrl and changes in every pull request that touches memory. Uncommitted, each person refreshes their own copy.

## Recall for each request

memctrl's per-request recall is a Claude Code prompt hook. Codex, Cursor and the other tools here get the brief, but nothing adds the memories that match each request. Two ways to fill the gap:

- **Run recall yourself** before a task that touches something the brief may not cover, and paste what it prints into your request:

  ```bash
  memctrl recall "rotate the JWT signing key"
  ```

- **Call it from your host's own prompt hook**, if it has one. `memctrl recall "<request>"` prints Markdown, or nothing when nothing matches; `--format json` gives entries to process. The `hook` format is Claude Code's JSON.

The skill also asks the agent to run `memctrl context` and `memctrl recall` itself when no hooks are installed. Don't count on it: in the agent benchmark, Claude Code never searched memory on its own.

## axga, pi and kimi

`memctrl install` also writes the skill for axga, pi and kimi, at the paths in the table above. memctrl has no hook for these tools. Give them the brief with `memctrl context --write` into whichever instructions file the tool reads, or run memctrl as an [MCP server](/memctrl/agents/mcp/) if the tool supports MCP.
