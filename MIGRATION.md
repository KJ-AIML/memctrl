# Rust-only migration

The baseline is version 1.3.0 at `f4089a853a77b4ab631b613dc787b67d0de4488a`. Python source, packaging, examples, benchmarks and PyPI publication are removed from this branch. Git history retains earlier releases.

## Database migration

1. Stop old MemCtrl writers and back up the database using SQLite backup, or copy only after all writers close and WAL is checkpointed. Copying just a live `.db` can omit pending WAL changes.
2. Build the native executable with `cargo build --release --locked`.
3. Test `--db /path/to/backup.db stats`, `doctor`, `list --include-history` and representative queries against a backup first.
4. Update CLI/MCP clients to use the native executable and explicit database/configuration paths.

Schema v4 memory, evidence, relations, audit, tree, provenance and span rows are retained. Older schemas receive additive migrations; future schemas are rejected. NULL/empty legacy semantic values use the historical assertion/accepted/unverified defaults. Native revision/cache and checkpoint tables are additive.

Original naive timestamps are interpreted as UTC. The original runtime used the host's local clock. If an existing database was created outside UTC, convert/interpret its naive timestamps before relying on expiry, decay and validity windows. RFC3339 offsets are supported for native inputs.

## API changes

| Former interface | Native replacement |
|---|---|
| Python memory store/dataclasses | `store::MemoryStore`, serde models and typed enums |
| Python CLI/Rich tables | compiled CLI with JSON output |
| LangGraph MemoryNode inheritance | `agent::memory_node`, JSON CLI or MCP |
| LangGraph checkpoint saver class | dedicated JSON checkpoint table and thread-keyed APIs |
| LiteLLM routing | native presets for OpenAI, xAI (Responses API), Anthropic (Messages API) and OpenAI-compatible servers; see README "Optional LLM providers" |
| Watchdog reload | TOML reload per invocation or MCP request |
| Global monkey-patched tracing | explicit `telemetry::traced` and `span::SpanTracker` |
| Python benchmark scripts | native Cargo examples and JSON fixtures |
| PyPI package | Cargo source installation |

This is not a source-compatible Python bridge. Existing Python integrations must use the executable/MCP/JSON interface or be rewritten in Rust. The CLI uses JSON output; `clear` requires `--yes`, and `install` requires `--tool`. `done/reflect --llm` explicitly errors because reflection is local source-preserving distillation.

Previous checkpoint payloads stored as ordinary memory remain in the database; they are not automatically converted into the native checkpoint table.

Reflection deliberately preserves source facts and creates candidate lessons instead of immediately promoting generated summaries. Maintenance is explicit: decay runs only through `memctrl decay` (schedule `memctrl decay --min-hours 24` to keep the old daily behavior); it no longer runs on query cache misses or MCP startup. LLM-assisted tree summaries retain deterministic membership; this does not promise identical clustering or responses from previous third-party model routers.

## Removed and changed behavior

- **History-mode retrieval is removed.** The original `retrieve(..., history=True)` annotated results with `[REFUTED]`, `[SUPERSEDED]`, `[CANDIDATE]`, `[REJECTED]` and `[ARCHIVED]`. Use `list --include-history`, which returns raw rows with their lifecycle and verification states.
- **Removed Python-only helpers:** `expire_old_memories` (expiry is now an eligibility filter, not a deletion), `should_forget`, `get_flagged_memories` (`decay` reports memories below 0.3 instead of per-layer floor flags) and query-cache statistics.
- **Refutation is terminal.** `dispute`, `accept` or any other verification change on a refuted memory now errors. The original runtime allowed refute → dispute → accept, which put a disproven claim back into retrieval. To revise a refuted claim, add a new memory and `supersede` the old one.
- **Decay never raises confidence.** A memory already below its layer floor (session 0.3, user 0.5) is left unchanged. The original runtime lifted it to the floor.
- **Provenance names the real method.** `method` and each source's `match_reason` are `keyword_tree` (2.1: `lexical_bm25`) for local retrieval and `llm_selection` for `query --llm`; `tree_version` records the store revision used.
- **UUIDs are identities, not PII.** Memory ids whose last group is all digits are no longer redacted as phone numbers.
- **Numbers inside JSON content are redacted.** When memory content (or any text) is a JSON document, numeric values that match a PII pattern (e.g. `{"phone": 5551234567}`) are replaced with a redaction string. Numeric fields in command output and structured metadata (timestamps, counts) are left as numbers.
- **Secret values are redacted whole.** `password=p,ssw0rd;x` and `Bearer abc,def` redact the entire value, as the original runtime did; the native runtime previously stopped at `,`, `;` or `}`.
- **LLM configuration is explicit and argv-free.** `--llm-provider` accepts `openai`, `xai`, `anthropic` and `compatible`. Use `--llm-api-key-env NAME` or `MEMCTRL_LLM_API_KEY`; `--llm-api-key` still works but is hidden and prints a warning, because argv is visible to other processes. `OPENAI_BASE_URL` and `OPENAI_MODEL` apply only to OpenAI-shaped providers.
- **Writes take the lock up front.** Top-level mutations begin `IMMEDIATE`, so concurrent writers wait (up to the 30s busy timeout) instead of failing with `SQLITE_BUSY_SNAPSHOT`. `add --llm` and `clear --layer` are all-or-nothing.

Legacy databases from the original runtime are covered by migration tests built from real stores: `tests/fixtures/python-v{2,3,4}-full.sql` were generated by running each commit's own `memctrl/store.py` (v2 at `76ee03a`, v3 at `47adfe7`, v4 at `519e95d`).

## 2.0 → 2.1

Opening a 2.0 database with 2.1 adds two full-text indexes and a `memory_citations` table, and indexes existing memories once. Nothing is rewritten and `schema_version` stays 4. A 2.0 binary can still open the database and its writes keep the indexes current, because maintenance happens in SQLite triggers.

- **Retrieval ranking changed.** `memctrl query`, `memctrl_query` and the agent node rank with FTS5 BM25 plus trigrams instead of the 1.x keyword scorer. Generic queries that used to return every memory (`"current project context"`) now return nothing; use `memctrl context` for session-start context. `confidence` is now the mean of memory confidence × query coverage. The 1.x scorer remains available as `retriever::keyword_retrieve`, and `memctrl eval --retriever legacy` compares the two.
- **Provenance method renamed.** Local retrieval records `lexical_bm25` (2.0 recorded `keyword_tree`). Each provenance source also carries `why`.
- **Results carry explanations.** Query output gains `why` (one entry per fact, plus `freshness` for cited memories). Library users who construct `RetrievalResult` literally need `..Default::default()`.
- **Installer paths fixed.** Claude Code skills are written to `.claude/skills/memctrl/` and Codex skills to `.agents/skills/memctrl/`. 2.0 used `.claude/agent/skills/` and `.codex/skills/`, which those tools never read. Re-run `memctrl install`; it reports a leftover legacy file as `legacy_skill`, which you can delete.
- **Guarded writes.** Memories with hidden Unicode or instruction-like text are stored as candidates (`status: quarantined`, tags `guard:*`) instead of being accepted. Set `[guard] mode = "off"` to restore 2.0 behavior (since 2.1.1, in your user config; see below).
- **New commands and tools:** `context`, `cite`, `stale`, `refresh`, `export`, `import`, `eval`, `install --hook`, and the MCP tools `memctrl_context` and `memctrl_stale`. `memctrl_add` accepts `claim_type`, `tags` and `cite`.
- **Writers need FTS5.** The search indexes are kept in sync by triggers, so any program that writes to `memories` needs a SQLite build with FTS5. memctrl 2.x binaries bundle it, and so do most language runtimes. Tools without it, such as macOS's `/usr/bin/sqlite3`, can still read the database, but their writes fail with `no such module: fts5`; nothing is corrupted. To write with such a tool, drop the three `memory_fts_*` triggers first. memctrl notices the missing triggers (or index row counts that no longer match) on its next start, recreates the triggers and re-indexes.
- **`forget` is remembered.** It records a tombstone (id and content digest) so `import` can't bring the memory back. `clear` resets tombstones along with everything else.
- **`memctrl init`** also writes `.memctrl/.gitignore`, so the database stays out of git when `.memctrl/memory.md` is committed. `memctrl maintenance` rebuilds the search indexes.

## 2.1 → 2.1.1 (unreleased)

2.1.1 fixes the findings of a real-world review. No schema change: 2.0, 2.1 and 2.1.1 keep sharing one database. Entries are added here as each fix lands.

- **Commands work from any subfolder.** memctrl walks up from the working directory to the nearest `.memoryrc` (stopping at the repository root, and never climbing into your home folder from below) and uses that project's rules and store. Without a `.memoryrc`, a store at the repository root or in the working directory is used, so projects set up without `init` keep working. `--rc` still names a rules file explicitly. The default `export --out` and `install --project` use the project folder too.
- **Only `memctrl init` creates a store**, or a database path you name (`--db`, `MEMCTRL_DB_PATH`, `db_path`). Other commands fail with a hint instead of creating an empty store wherever they run; `context` stays silent. `init` keeps an existing `.memoryrc` (for example one a teammate committed) unless you pass `--force`, and it refuses inside another project.
- **Stray stores.** 2.1.0 created a store in whatever folder a command ran in. `memctrl doctor` lists them under `stray_stores`. To keep one's memories: `memctrl --db src/.memctrl/memories.db export --out stray.md --layer project --layer user`, then `memctrl import stray.md`.
- **Short ids.** Every command and `memctrl_review` accept a unique id prefix of at least 4 hex characters, such as the 8 characters the brief shows. An ambiguous prefix is refused with its matches.
- **Import holds new entries for review.** Anyone who can edit memory.md can write an entry whose metadata verifies, so new entries now arrive as candidates (tag `import:new`). After reading the file's changes, run `memctrl import --accept <file>`: it accepts new entries and the candidates an earlier plain import created. Edited entries, ids that appear with different texts (tag `import:conflict`) and guard-flagged entries stay candidates either way. Ids are compared in canonical form, a future `created_at` is clamped to now, and entries outside the imported layers (`--layer`, repeatable, default `project`) are skipped. The report has a `note` when candidates were created.
- **Export won't drop unmerged entries.** When `.memctrl/memory.md` has entries your store has never seen, or holds only as candidates (a teammate's entries after `git pull`, hand edits), `export` and `export --check` list them and refuse. Import first, or pass `--force`. A file that isn't a memctrl export is never overwritten without `--force`.
- **CI.** `export --check` needs your local store. Without one it now says so; validate the file with `memctrl --db :memory: import --dry-run .memctrl/memory.md`, which creates nothing.
- **Honest dry runs and errors.** `import --dry-run` runs the real import and rolls it back, so it fails exactly when the import would. Errors print their whole chain ("entry at line 6: memory id must be a UUID: …"). Unresolved merge-conflict markers and files from a newer memctrl are rejected by line.
- **Only a person releases held memories.** Candidates the write guard quarantined (`guard:*` tags) or an import holds for review (`import:*` tags) can't be accepted over MCP. `memctrl accept` releases them only at a terminal: it shows the text with invisible characters spelled out and asks for the id's first 8 characters. `import --accept` lists the entries it would accept and asks you to type `accept`. Without a terminal (an agent's shell, a pipe, a script) both refuse; no flag or environment variable skips this. Each release is written to the audit log. Callers can no longer set `guard:` or `import:` tags themselves.
- **`accept` resolves a dispute**: a disputed memory goes back to `unverified` (never `supported`).
- **Your settings live in a user config.** `~/.config/memctrl/config.toml` (or `$XDG_CONFIG_HOME/memctrl/config.toml`; `%APPDATA%\memctrl\config.toml` on Windows) holds `[guard] mode`, `[guard] trusted_sources` and `[trust] repos`. A repository's `.memoryrc` arrives with every clone, so it may now only tighten: the guard mode can only go up, `trusted_sources` only narrow, `[forget] never` only grow, `[citations] root` and `db_path` must stay inside the repository, and no trigger may move `user`-layer notes into a shared layer. Ignored settings are printed as warnings and listed by `doctor` under `config_warnings`. To keep a repository's file in full, list it under `[trust] repos`. If your `.memoryrc` sets `[guard] mode = "off"`, move that line to your user config.
- **A database committed to git is never loaded.** Anyone with push access could have written its memories, already accepted. `context` prints nothing (with a warning on stderr), other commands refuse, and `doctor` reports `committed_database`. Run `git rm --cached .memctrl/memories.db` and share memory through memory.md, or trust the repository in your user config.
- **The brief keeps its warnings.** Up to 5 memories to check before trusting and 3 user preferences get reserved room, and no section takes more than 40% of the budget until every section has had a turn, so a store full of decisions can no longer push the warnings out. When something doesn't fit, the header says what ("Not shown for space: 3 to check before trusting (run `memctrl stale`), 12 decisions"), and it mentions candidates waiting for review. `context --format json` adds `omitted` and `pending_review`.
- **`refresh` never re-anchors at the wrong lines.** It follows a block that moved, exactly or by its first line when that line now occurs once. Otherwise it changes nothing and asks for the range: `memctrl refresh <id> --cite path:start-end`. Output gains `from` and `followed` when a range changed; the audit entry records the move.
- **Lifecycle.** `refute` keeps its reason as evidence (shown by `show` and `history`) and in the audit log; `reject --reason` is audited too. Adding text a layer already holds returns that memory (`"status":"exists"`); re-adding refuted, rejected or superseded text is refused with a hint. The default `on_session_end` rule (`summarize session -> user`) now proposes user-layer candidates (tag `proposed:on_session_end`) instead of moving session notes, and `consolidate` (the default `on_commit`) gives promoted memories the target layer's retention, so project memories no longer expire after 7 days.
- **Library (brief, refresh, lifecycle):** `context::build_with` and `Brief::{omitted, pending_review}`; `citations::refresh` takes explicit ranges; `MemoryStore::consolidate_and_log` takes the target expiry; `MemoryStore::{find_same, existing_for_add, count_candidates}`.
- **Redaction covers more and says so.** Keys with a prefix (`DB_PASSWORD=`, `STRIPE_API_KEY=`, `JWT_SECRET=`, `PGPASSWORD=`, `pwd=`) are now redacted, keeping the key name (`DB_PASSWORD=[REDACTED_PASSWORD]`). So are GitLab, Slack, Stripe, npm and Google tokens, JWTs, AWS `ASIA` keys, encrypted and PGP private keys, `Authorization:` headers of any scheme, URL passwords containing `@` or `/`, Luhn-checked card numbers, `(555) 123-4567` and `+66 …` phone numbers, and Thai national ids. Placeholders (`${VAR}`, `<your key>`, `true`, short numbers) and prose ("Bearer token in the header", "Session token: rotate weekly") stay as written. `add`, `memctrl_add` and the import report list what they removed under `redacted`. Text already stored is not rewritten.
- **The guard raises far fewer false alarms.** On the review's corpus of 50 ordinary notes, 4 are held instead of 36: the rustup, uv, nvm and Homebrew installers (exact host and path), "ignore prior rules for generated files", role markers named as tags or tokens or written in backticks, a download followed by a *different* script, emoji ZWJ sequences, keycaps, subdivision flags, Thai zero-width spaces, ideographic variation selectors, soft hyphens and direction marks in right-to-left text. It also catches more: piping through `sudo -E`, `/bin/bash` or `tee`, `source <(curl …)`, `python3 -c "$(curl …)"`, `iex (irm …)`, and running a file a download just saved (26 of 73 attacks, up from 19, all 19 earlier catches kept). It is still a tripwire: paraphrases, other languages and encodings get past it.
- **Secret files stay secret.** A citation whose path resolves (through a symlink) to a secrets file is refused, such files are never hashed, and citations of them are left out of exports.
- **Safer file writes.** Temp files get random names and are created exclusively, so a planted symlink can't redirect a write; `.memctrl/.gitignore` is never written through a symlink.
- **Library:** `memctrl::review` (`accept`, `Release`, `held_for_review`, `check_tags`, the terminal prompts); `rules::UserConfig` and `Rules::load_with`; `Rules::warnings`; `guard::Mode` is ordered; `guard::reveal`; `project::tracked_by_git`; `MemoryStore::accept_memory`; `mirror::import_with` asks before accepting; `sanitize::redactions`; `citations::secret_file` is public.
- **Library:** `ImportOptions` replaces `default_layer` with `layers` and adds `accept`; `mirror::unmerged` lists entries an export would drop; `fsutil::confined_target` checks a path before reading it; `MemoryStore::insert_memory_as` requires canonical ids; `MemoryStore::accept_imported` promotes an import candidate.
- **Library:** `memctrl::project` finds projects; `MemoryStore::resolve_id` resolves prefixes; `mcp::serve` takes the project folder; `Rules` has a `project_dir` field; `citations::root_for(&rules)` resolves the citation root with the project folder as a fallback.

## Team sharing v2 (unreleased)

`.memctrl/memory.md` moves to export format v2. memctrl now reads v1 and v2 and writes v2. Databases change only by three additive columns on `memory_tombstones`, so 2.0 and 2.1 can still open them.

- **Corrections travel.** A final `## Retracted` section records refuted, superseded and forgotten memories, with the refute reason and the superseding id. Import applies them one way only (active < disputed < superseded = refuted < forgotten): it can lower a memory's state but never revive one. A teammate's `forget` archives the memory here (it can be undone) and records a tombstone, as do retractions of memories this store never had, so an older export can't bring them back. A disputed entry marks the local copy disputed. Forgotten records carry no text, so a forgotten secret is never published again. The import report lists what changed under `retracted`.
- **Export merges.** Writing over an existing memory.md keeps the entries your store hasn't decided on (a teammate's new entries, hand-written bullets, edits waiting for review) and every retraction record, instead of refusing or dropping them. `export --force` writes from your store alone. The report says how many entries were `carried`.
- **`memctrl sync`** imports memory.md (new entries as candidates, retractions applied), then exports your store merged with it: the one command to run after pulling. `--accept` is the reviewed bulk accept, at a terminal.
- **`memctrl check`** validates memory.md without a database, for CI: header, merge markers, canonical and unique ids, each entry's sha, and the layout export writes. Edited and hand-written entries are warnings (errors with `--strict`). `--base origin/main` fails when a retraction record was removed or a retracted memory is live again.
- **Fewer merge conflicts.** Entries are ordered by id within each section, so two pull requests that each add an entry rarely touch the same lines, and the count line is gone.
- **Compatibility.** memctrl 2.1.0 can't read a v2 file ("not a memctrl export"), and a 2.1.0 `export` overwrites it, dropping its retraction records. Run `memctrl check --base origin/main` in CI to catch that; any teammate on this version restores the records with their next export. The first export after upgrading rewrites the file once, in the new order; commit that change on its own.
- **Library:** `mirror::{render_merged, check, CheckReport, Retracted}`; `MemoryStore::{record_tombstone, tombstone_records}` and `store::Tombstone`.

## 2.1.1 → 2.1.2 (unreleased)

No schema change; 2.0, 2.1 and 2.1.x keep sharing one database.

- **Reads stop taking the write lock.** Opening a store checks its schema with a read and takes the write lock only when a migration is needed. Searches and the session brief read from a snapshot; access counts, provenance, cache entries and telemetry are written afterwards as best-effort bookkeeping with a 25 ms lock timeout, skipped when another process is writing. With a writer holding the lock, `context --format hook` on a 100k-memory store answers in under a second instead of failing after 30 seconds. Under heavy contention some access counts and provenance records are not recorded.
- **The query log stays small.** Provenance records hold memory ids, scores and `why`, not memory text (`memctrl show <id>` has the text). The log keeps the newest 10,000 records and nothing older than 30 days, trimmed as new records are written. Logged queries are cut to 1,024 characters. The query cache stores ids and re-reads the memories, so 2.1 and 2.1.2 never read each other's cache entries.
- **One-time compaction.** The first open by 2.1.2 strips memory text from existing provenance records and removes the old per-memory tree leaves, in small transactions. No rows are deleted. `memctrl maintenance --vacuum` gives the freed space back to the file system; `doctor` reports `reclaimable_bytes`.
- **64 KiB memory limit.** `add`, `memctrl_add`, triggers and every other write path reject memories over 64 KiB with a hint to split the text or cite a file. Import skips such entries and lists their lines under `skipped.oversized`. Reflection and Heli lessons are cut to fit. Existing larger memories stay readable; `doctor` counts them as `oversized_memories`.
- **The tree is read-only unless you ask.** `memctrl_tree` and `memctrl tree` show layers, clusters, counts and sample ids, and whether the stored tree is out of date. `rebuild: true` (`memctrl tree --rebuild`) builds it again and stores only root, layer and cluster nodes. `forget` no longer wipes the tree.
- **Vague questions return nothing.** Topic-free words (project, information, summary, overview, system, use, and their Thai, Chinese, Japanese and Korean counterparts such as ข้อมูล, โปรเจกต์, 项目, プロジェクト) still help ranking, but a memory must match at least one other word to be returned. A query made only of them ("summarize the project", ภาพรวมของโปรเจกต์นี้) returns nothing, with `generic_only` in the trace, and `why` labels them `(generic)`. Words inside identifiers (`GOOGLE_CLOUD_PROJECT`, `project.info`) are never generic. Add your own with `[retrieval] generic_words`, or switch the built-in list off with `builtin_generic = false`. On a reviewer's Thai team suite, vague questions answered with nothing rose from 0.59 to 1.0 (held-out questions never used for tuning: 0.77 to 0.92; an English mirror: 0.50 to 0.92), with no loss on answerable questions.
- **Better Thai and CJK matching.** English written against Thai or Chinese (ใช้Redisเป็น, 订单服务使用PostgreSQL) is found even when the same word also appears on its own elsewhere, but not inside another word (Redisson). A single Thai, Lao, Myanmar or Khmer letter matches only where it stands apart (ณ in หัก ณ ที่จ่าย), not inside words; a lone kana or mark is ignored. Long Thai runs count as several words in the coverage threshold, as English words already do. The retrieval version is now `lexical-v2`, so cached results are recomputed.
- **The built-in eval suite is `dev-memory-v2`.** It adds memories that use generic words in passing and vague questions that share them; 2.1.0 answered 3 of its 9 vague questions with nothing, 2.1.2 answers all 9. The reviewer's suites are in `tests/fixtures/eval/` with floors in `tests/eval.rs`.
- **Library:** `search::parse_query_with`, `Term::generic`, `Run::generic`, `ParsedQuery::only_generic`; `SearchOptions` gains `generic_words` and `builtin_generic` (no longer derives `Default` field-by-field: use `SearchOptions::default()`); `Rules` gains the same two fields.
- **Library:** `store::ReadSnapshot`; `MemoryStore::{side_write, best_effort, store_tree, tree_overview, count_oversized, reclaimable_bytes, vacuum}`; `store::logged_query`; `model::{MAX_MEMORY_BYTES, clip_to_limit}`; `tree::{compact, overview}`.
